# Release / 真机性能与内存基线

状态：**待真机与 Release 条件具备后执行**。当前没有真机，本文件只冻结测量口径、操作顺序和记录格式；模拟器结果不得填入“实测”字段。

## 固定口径

- 性能设备：iPhone 14 Pro Max，iOS 26.5.2，Release。
- 布局兼容设备：iPad Air（M2），iOS 26.5；只测横竖屏和约定窄分屏，不把 iPhone 横屏纳入首发。
- 工具链：Xcode 26.2、Swift 5；使用实际源码文件夹交付方式。
- 内容：固定公式密集长章节；另保留普通 Markdown、复杂表格两组对照。正常范围单次 Markdown ≤ 8,192 字符，硬上限 ≤ 64 KB、≤ 500 块、≤ 100 个公式。
- 每组至少 5 次预热后记录 20 次；报告 p50/p95/p99、最大值和异常样本，不只记录平均值。

## 性能操作

1. 新建干净宿主，Release 真机启动，停留在空白页记录宿主基线。
2. 从宿主收到 Markdown 开始计时，到首屏稳定且可交互结束；网络请求、书籍读取和业务分页不计入。
3. 固定章节重复打开；每次先 `clearContent()`，再等待页面释放，避免把前一次内容当作当前增量。
4. 连续向下滚动 60 秒，再反向滚动 60 秒；记录主线程最长阻塞、≥50 ms 和 ≥100 ms 卡顿次数、滚动期布局变化。
5. 对照缓存命中、普通内容、公式密集内容和复杂表格内容；改变测试组时重新启动应用。

建议使用 Instruments 的 Time Profiler / Core Animation / Allocations；若用 `xctrace`，把命令、模板、设备 UDID、`.trace` 产物路径和提交号写入报告。不要使用“体感流畅”替代数值。

## 内存操作

1. 冷启动后记录宿主空白页稳定值。
2. 打开固定章节，记录渲染峰值、稳定平台和组件增量；峰值必须与宿主基线分开计算。
3. 重复打开/关闭同一章节 10 次，每次都执行 `clearContent()` 并释放页面；记录每轮稳定值，不接受持续阶梯式增长。
4. 在可控条件下触发一次内存警告，记录警告后的稳定值和缓存回收情况。
5. 用 Allocations/Leaks 区分瞬时排版分配、持久组件对象、公式位图和图片缓存；“总分配量”不能直接当作泄漏或组件增量峰值。

## 通过阈值

| 指标 | 阈值 |
| --- | --- |
| 首屏稳定可交互 | p95 ≤ 800 ms；p99 ≤ 1.2 s |
| 120Hz 滚动单帧主线程工作 | p95 ≤ 8.3 ms；p99 ≤ 16.7 ms |
| 滚动卡顿 | ≥ 50 ms 为 0；≥ 100 ms 为 0 |
| 滚动期已显示块高度变化 | 0 次；不得连续 reload/invalidateLayout |
| 单章组件增量峰值 | ≤ 80 MB |
| 清空、退出、内存警告后稳定增量 | ≤ 20 MB |
| 公式/图片等组件缓存 | 按真实字节计量，合计 ≤ 32 MB |
| 连续开关 10 次 | 回落到稳定平台，不得持续阶梯式增长 |
