# 项目接入需求与 GMarkdown 能力对照（2026-09-29）

> 历史能力差距记录：下表的“组件缺口”是 2026-09-29 的判断。仓库已实现受控 `richTxt` 展示、`CustomClickableSpan` 范围与虚线，以及 Markdown 路径可识别的失败/降级通知；源码已同步至候选交付包。当前行为见 [RichTxtHTMLSupportScope.md](./RichTxtHTMLSupportScope.md) 和 [Integration.md](./Integration.md)。业务输入选择、点击/隐藏/恢复、真实页面接入仍待后续确认。

本表以业务方口述的目标工程要求、Demo「项目书籍测试」的导出数据和当前组件代码为依据。它用于决定接入前要实现什么；不把 Demo 功能回归重复列为待办。目标业务工程源码尚未提供，因此页面列表结构和现有 Cell 接口仍须在实际接入时核对。

## 已确认的项目契约

1. `dataBaseBean.richTxt` 有内容时优先展示 HTML 富文本；`richTxt` 为空时展示 `dataBaseBean.txt` 的 Markdown。渲染失败后的动作不由此优先级规则推定，由宿主根据失败/降级信号决定。
2. `txt` 需要展示常见 Markdown：标题、正文、强调、列表、引用、代码、表格、图片、链接和公式。无需承诺所有 Markdown 扩展。
3. `richTxt` 是编辑器生成的 HTML 富文本。已给出的实际样本包含 `<html>`、`<body>`、`<p>`、`<br/>`、`<span>`、数字字符实体，以及 `font-size`、`color`、`margin` 和 `dir`。正文内容和这些用于阅读的样式需要呈现；不要求执行脚本或使用 WebView。
4. `richTxt` 中的 `<CustomClickableSpan>` 标记可挖空文字；当前外观为底部虚线下划线。标签内文字须保留，组件须能识别该范围。点击、挖空/恢复和业务状态规则尚未口述，不能自行定义。
5. 单独的图片若 GMarkdown 无法显示，项目使用自己的自定义 Cell 兜底。组件应把可识别的失败/受控降级通知宿主；图片若嵌在一个 Markdown/表格块内，是否能改用独立 Cell 取决于业务页面的内容切分和列表结构。
6. `wordIndexBeans` 暂不接入；其产品语义在具体业务需要使用时再确认。

## 对照结果

| 项目要求 | 现有证据与组件能力 | 结论 | 接入前动作 |
| --- | --- | --- | --- |
| 常见 Markdown 字符串显示 | `GMarkProcessor` 接收 Markdown，分块 `GMarkdownMultiView` 显示；Demo 基础能力已通过模拟器验收，9 本项目书籍的现有 `txt` 内容已盘点。 | 已支持 | 保持现有主路径；只回归受后续改动影响的样本。 |
| `richTxt` 优先、为空才使用 `txt` | 项目书籍 Demo 加载器只提取 `dataBaseBean.txt`；已导出的 9 本书中 `richTxt` 全为空。 | 未接入 | 在项目数据适配层保留两个字段并执行此优先级；不得把渲染失败自动等同于 `richTxt` 为空。 |
| 编辑器 HTML 富文本的正文、段落与常见阅读样式 | `GMarkHTMLSanitizer` 可保留部分文字和基本换行，但忽略 `style`、`dir`，不解码数字字符实体；`</p><br/>` 的段落间距也不能保证与编辑器一致。 | 组件缺口 | 增加独立的受控富文本处理路径，按实际编辑器输出保留正文、段落、实体、允许的字号/颜色/间距；继续限制脚本和外部资源。 |
| `<CustomClickableSpan>` 可挖空标记及底部虚线 | 当前 HTML 清理器将未知标签剥掉，仅保留内部文字；没有标记范围、虚线样式或相应宿主事件。 | 组件缺口 | 识别并保留标签对应范围，绘制底部虚线；业务操作通过宿主接口承接。交互状态规则明确后再实现挖空/恢复。 |
| 渲染失败/受控降级通知宿主 | 块级公式失败会打印日志并退回纯文本；没有统一的带内容块身份、原因和降级结果的公开回调。图片异步加载结果目前由 `ImageLoader` 实现自行处理。 | 组件缺口 | 定义结构化失败/降级结果和宿主通知；区分解析、公式、HTML、图片等来源，默认不在诊断事件中传正文或 URL。 |
| 单独图片失败后由项目自定义 Cell 兜底 | 组件已有图片加载接口；`GMarkdownMultiView` 自己管理内部 `UICollectionView`，不能直接让宿主替换其中某个 Cell。项目书籍数据中也有图片位于 `TXT` 或表格内部。 | 项目方案可行，替换边界待核对 | 对业务列表中的独立图片由项目选择自定义 Cell；嵌入内容如需整块替换，先核对业务页面的块身份和列表结构，再决定是否需要组件级替换接口。 |

## 实施顺序

1. 先定义可供宿主判断的失败与受控降级信号，包括内容块身份、失败类别、实际降级结果和异步图片失败的责任边界。
2. 完成 `richTxt`/`txt` 输入选择契约、受控 HTML 富文本展示和 `CustomClickableSpan` 的范围/虚线能力，并接入上述信号。
3. 只对上述新增能力使用口述的代表性样本做定向验证；完成独立 Xcode 源码接入演练后，再接入业务工程。

上述结果是能力对照，不代表尚未提供的业务工程页面结构、真实图片资源或最终交互规则已经验收。
