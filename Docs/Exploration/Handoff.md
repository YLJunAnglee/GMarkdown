## F-007：TextView 将混合内容中的 `$$...$$` 强制排成块级（2026-09-17，通过）

- **样本与原始内容：**《高中物理必备知识》第 65 章“核反应相关知识点”，第 2 个 TXT 块。用户通过“原始内容”核对开头为 `## 9.衰变次数的确定方法…设放射性元素$${}_{Z}^{A}\text{X}$$经过…`；`$$...$$` 位于二级标题同一行的混合正文中，并非独立公式段落。
- **运行证据：**用户提供的分块截图中，该核素公式保持行内。TextView 截图则把每个同类公式置于独立居中行，令“设放射性元素”和“经过”之间产生明显的额外高度；这已确认是 TextView 附件模式选择问题。
- **原因：**`DefaultInlineHTMLPlugin` 仅根据定界符调用 `GMarkFormulaMode.detect`。因此所有 `$$...$$` 都生成块级滚动附件，未区分独立公式段落、标题、粗体或与正文混排的段落。
- **修改：**`GMarkFormulaMode.attachmentMode(for:)` 现在只将“自身就是完整段落”的双美元公式作为块级附件；标题、粗体和混排段落中的双美元公式按行内附件布局。表格单元格保留既有块级公式行为，避免回归 T-001–T-003。`FormulaModeTests` 新增 AST 上下文断言，覆盖标题、粗体和独立块级段落。
- **验证结果（2026-09-17，用户运行）：**更新后的 TextView 截图显示首个核素公式已留在“设放射性元素”与“经过”之间，额外居中行消失；此前的分块截图也确认相同位置保持行内。两条路径通过。`git diff --check` 通过；助手未编译、未运行 Swift 测试或 Demo。当前不修改原始 JSONL。

## F-008：表格内 `$\\begin{aligned}…$$` 的受控定界符降级（2026-09-17，通过）

- **原始内容与原因：**同章第 3 个 TABLE 的“人工转变”单元格为 `$\\begin{aligned}…\\end{aligned}$$`：单个开头与双重结尾不配对，留下的 `$` 会吞连“重核裂变”行，导致 `\\begin` 源码泄漏。原始数据页面已由用户截图核对。
- **修改：**预处理器仅对“单 `$` 紧接 `\\begin{aligned}`、双 `$$` 结束，且其后为表格/Markdown 边界（`|`、空白、换行或结束）”的确定性错误，派生出 `$$\\begin{aligned}…\\end{aligned}$$` 参与渲染；不会改写 JSONL，也不会为普通文本、任意未闭合 `$` 或其它 TeX 猜测补定界符。随后的 `$\\begin{aligned}…$` 是完整单美元公式，会按既有逻辑独立识别，不再被前一行遗留字符吞连。
- **验证结果（2026-09-17，用户运行）：**同章“核反应方程典例”在分块与 TextView 截图中均不再显示 `\\begin` 源码；人工转变、重核裂变、轻核聚变公式分别完整，表格行没有合并。两条路径通过。新增表格 AST 测试覆盖恢复后的 `aligned`、随后的单美元公式及相邻 `$...$` 公式不被吞连。`git diff --check` 通过；助手未编译、未运行 Swift 测试或 Demo。

## 保留的边界与取舍

- 完整 MathJax 包集是通用扩展加载，不仅针对 `\\ce`、`\\xlongequal`；但不在 MathJaxSwift 打包范围内的私有宏或损坏公式，仍可能显示红色未定义命令。这是后续定位信号，不改写源数据掩盖。
- MPITextKit 不支持表格中的彩色 `❌`、`✅` glyph。渲染层仅将这两个状态符号降级为 `×`、`✓`（B-009、B-010）；原始 Markdown 保持不变，未对其它 emoji 作推断性替换。
- 导出的 manifest 标明 `imageFilesIncluded: false`；无真实资源或不可达 URL 不能验收为位图加载成功，只能验收解析、布局和 `alt` 降级。
- F-007 已确认当前真实章节中混合标题正文的双美元公式不再被 TextView 强制拆块；TextView 行内公式略偏上、超宽行内公式等比缩小、链接内部公式仍未系统覆盖，不能宣称全量通过。
