# GMarkdown 项目接入准备与验收计划

最后更新：2026-09-18。

## 目标

本计划用于回答“当前探索分支何时可以接入正式项目”。接入完成不以某一章截图正常、编译通过或 Demo 能启动为标准，而以以下结果同时成立为标准：

1. 正常输入能忠实显示，已知脏输入只在高置信边界内恢复，不能可靠恢复时安全降级。
2. 分块渲染和 TextView 中纳入接入范围的路径均有可重复的验证证据。
3. 不出现崩溃、跨块吞内容、不可达裁切、明显主线程卡顿、持续内存增长或异步复用串内容。
4. 组件承诺的系统版本、容器形态、主题、字号、内容规模和显式更新行为均经过验证。
5. API、依赖、资源、权限与安全策略在组件发布前明确；业务数据加载、监控、灰度和回滚由宿主项目另行验收。

真实书籍探索的历史结论仍由 [探索索引](README.md)、[接续记录](Handoff.md) 和 [公式问题记录](FormulaIssues.md) 保存。本文只维护接入门槛、执行顺序与最终证据，不重复问题流水账。

## 每次代码修改后的强制 Review

每次修改代码后，必须在同一轮完成一次高度 Review，再进入 Demo 验证或标记风险通过。Review 至少覆盖：架构是否仍符合首发路径与安全边界、实现是否完整覆盖目标、正常与异常输入是否正确、索引/尺寸/生命周期/线程/复用等边界是否安全、代码是否存在重复逻辑或不必要的兼容分支、文档与测试证据是否同步。发现问题必须在同一轮立即修正并重新 Review；交付时给出简短 Review 报告，列出检查范围、发现的问题、修复结果和仍未验证的事项。静态 Review 不能替代用户 Demo、最小宿主和阶段 E 的构建/性能验证。

## 组件库与宿主项目的两条准入线

组件库质量与业务项目上线不能混为同一个状态。组件库先达到可发布，宿主才在自己的数据链路、灰度和监控下决定是否上线：

| 状态 | 必须满足 | 允许做什么 |
| --- | --- | --- |
| L1 组件可试集成 | 组件接入契约全部冻结；主渲染路径按选定分发方式在最小宿主中完成干净构建/启动；组件 P0 为 0，架构级 P1 已修复、关闭或明确阻断 | 供真实项目在内部开发分支集成，不代表业务数据链路已可上线 |
| L2 组件可发布 | 适用的 G1–G7 全部通过；组件 P0/P1 为 0；组件性能预算已有目标设备实测；候选提交被冻结 | 可作为受控版本交付给项目 |
| P1 项目可灰度 | 项目完成数据请求、缓存、章节切换/刷新、埋点、功能开关和回滚验证；集成版本为 L2 | 进入内部账号或小流量灰度，不直接全量 |
| P2 项目可全量 | 灰度指标稳定；项目回滚演练完成；已知 P2/P3 和降级行为获业务接受 | 按既定节奏扩大范围并发布 |

当前状态：**分块主路径模拟器验收通过，整体仍未声明 L1/L2**。原因是本轮无法执行真机与 Release 性能/内存测试，且 TextView 仍是诊断路径，不进入首发承诺。某一真实章节视觉通过，只能作为 G1 的局部证据，不能单独提升整体准入状态。

本轮恢复点后的可交付准备：已新增 [Release/真机基线](../Performance/ReleaseBaseline.md)、[最小宿主样板](../../Examples/MinimalHost/README.md) 和 `Delivery/GMarkdown-0.1.1/` 候选目录骨架。它们只冻结口径与接入材料，不替代真机测量、干净宿主构建或完整许可证/资源复制；当前仍不能声明 L1/L2。

## 接入范围先冻结

正式执行验收前，必须在宿主项目中确认并记录以下契约；未确认项不能靠库内默认值猜测：

| 项目 | 必须确认的内容 |
| --- | --- |
| 渲染入口 | 分块渲染、TextView 或两者都接入；若只上线一条路径，另一条只作为诊断工具，不进入发布承诺 |
| 内容来源 | 仅受信任的项目书籍，还是也允许用户输入、服务端 Markdown、任意 HTML/Mermaid |
| 输入边界 | 组件接收调用方提供的 Markdown 或 chunks，不依赖 JSON/网络/章节 schema；当前书籍 Demo 的“每个 TXT/TABLE 块独立解析”只是业务适配示例 |
| 系统与设备 | 最低 iOS、主力 iOS、最窄手机宽度、横屏、iPad/分屏是否属于首发范围 |
| 展示能力 | 标题、列表、引用、链接、代码、表格、图片、公式、HTML、Mermaid 中哪些必须上线，哪些可以关闭 |
| 图片策略 | 宿主提供的 `ImageLoader`、允许的 URL scheme/domain、超时、缓存、失败占位及离线表现 |
| 交互策略 | 链接打开、代码复制、公式/表格横向滚动、HTML/Mermaid 弹窗、图片保存权限 |
| 更新 API | 组件只承诺显式设置/替换内容时不串内容、不残留旧 cell，且不自行在滚动中发起隐式布局刷新；一次性加载、流式追加、分页、网络请求和业务刷新节奏由宿主决定 |
| 发布方式 | SPM、CocoaPods 或源码内嵌；只承诺实际验证过的分发方式 |
| 工具链 | Xcode、Swift 语言模式、最低部署版本以及是否要求 Swift 6 并发检查 |
| 质量预算 | 首屏、主线程阻塞、滚动、峰值/稳定内存、包体增量的暂定阈值及测量设备 |
| 组件交付策略 | 组件能力开关、错误分类、已知降级和版本回退方式；项目灰度人群、监控及业务回滚由宿主项目决定 |

契约冻结前，已有的双路径结果继续作为探索证据，但不再新增随机样本或实现新兼容逻辑。先选定正式主路径和首发能力；未入选路径可保留为诊断工具，不进入发布承诺，也不阻塞 L1。

### 阶段 A 已确认项

| 项目 | 当前决定 | 对验收范围的影响 |
| --- | --- | --- |
| 首发主渲染路径 | **分块渲染（`GMarkdownMultiView`）** | G1–G7 以分块路径为正式验收对象 |
| TextView | 保留在 Demo/诊断，不进入首发 | 不以 TextView 的附件、行内公式、异步图片或连续文本选择问题阻塞 L1–L2；未来启用时必须新开一轮对应门槛 |
| 内容来源与信任级别 | 服务端 Markdown、用户输入和第三方 HTML 都会进入；按**不可信输入**处理 | 不能把服务端或第三方来源默认视为可执行内容；HTML、图片、链接和代码预览均需安全策略 |
| Mermaid | 首发关闭 | Mermaid 代码块不得提供预览或执行入口；未来启用时独立完成 WebView/脚本/文件访问验收 |
| 第三方 HTML | 首发采用**受限、非执行式展示** | 不执行 JavaScript、不打开 WebView、不加载任意外部资源；按下方 HTML 白名单和降级规则处理 |
| Markdown 链接 | 保留链接文本与样式，不由组件直接打开 | 组件以宿主链接回调交出 URL；宿主统一执行 scheme/domain 校验、站内路由或用户确认，未配置回调时不导航 |
| Markdown 图片 | 支持，但只能经宿主 `ImageLoader` 加载 | 首发默认只允许 `https`；宿主负责域名白名单、重定向、响应大小/MIME、超时、缓存与失败占位；第三方 HTML 的 `img` 不加载 |
| 正文选择与复制 | 支持单个文本块内的长按选择、双击选词、系统选择手柄/菜单与复制 | 不支持跨块选择；首发菜单仅系统“复制”，选择文本仅限当前文本块的可读内容；宿主可接收选择动作回调，供后续查词、批注等自定义提示框扩展 |
| 代码块 | 支持展示、语法高亮与复制 | 不执行任何代码；包括标记为 `html` 的代码块也只展示/复制，不提供 WebView 预览或运行入口 |
| 公式 | 支持行内 `$...$`、块级 `$$...$$` 与表格内公式 | 仅对结构与边界可确认的定界符解析；识别或渲染失败时保留可读原文或明确占位，不能半解析或显示残缺源码 |
| 表格 | 支持标准 Markdown 表格 | 空间不足时保持可读字号并在表格内横向滚动；不得强行缩小正文，且横向手势不能锁死页面纵向滚动 |
| 内容规模边界 | 正常性能范围：单次 Markdown ≤ 8,192 字符 | 安全硬上限：≤ 64 KB、≤ 500 个渲染块、≤ 100 个公式；超限不崩溃/不无界耗时，触发受控降级与诊断事件，由宿主决定是否拆分 |
| 设备与方向 | iPhone 仅竖屏；iPad 支持横竖屏和分屏 | 分块路径必须以实际容器宽度布局；iPad 旋转和至少一种窄分屏宽度进入 G2 正式回归 |
| 最低系统版本 | **iOS 14.0** | 源码交付、最小宿主与测试矩阵统一以 iOS 14 为最低版本；不承诺 iOS 13 |
| 分发方式 | **源码文件夹集成** | 不承诺 SPM/CocoaPods；交付可直接加入 Xcode target 的版本化目录、依赖源码/二进制及其许可证、资源清单和必需 build settings |
| 源码升级与回退 | 每次交付不可修改的 `GMarkdown-<semver>/` 版本目录 | 目录含组件、依赖、资源、`Integration.md`、许可证、变更说明和文件哈希清单；项目仅整体替换目录升级/回退，不在业务工程散改组件源码 |
| 工具链基线 | **Xcode 26.2、Swift 5** | 首发以此干净构建；不以 Swift 6 严格并发检查作为发布门槛，但异步任务仍须按 G3 的线程与生命周期契约验证 |
| 性能/布局基准设备 | **iPhone 14 Pro Max / iOS 26.5.2**；**iPad Air（M2）/ iOS 26.5** | iPhone 用于性能预算的 Release 实测；iPad 用于横竖屏、分屏与兼容性回归，二者均不以模拟器体感替代 |
| 组件自有资源包 | **≤ 1.2 MB** | Mermaid 已关闭且不交付其资源；仅保留实际启用的代码高亮资源和默认浅/深主题，禁止为未启用能力携带执行资源 |
| 主题与可访问性 | 支持系统浅/深色、Dynamic Type 与 VoiceOver 基础阅读顺序；宿主可注入主题 | 颜色、字体、间距等以语义 token 配置，不能散落硬编码；主题切换不重新解析 Markdown，也不得在滚动中触发布局抖动 |
| 诊断接口 | 组件上报不含正文的结构化事件，宿主决定埋点与告警 | 至少覆盖解析/受控降级、公式失败、图片失败、渲染耗时和缓存命中；不得默认上传 Markdown、公式原文或用户 URL |

其余契约项仍待宿主确认。HTML 的安全展示规则已冻结，但需在阶段 B 实现并验证后才能计为通过。

### 第三方 HTML 首发安全规则

1. 只允许表达文本语义的有限标签：`br`、`strong`/`b`、`em`/`i`、`u`、`s`/`del`、`sup`、`sub`、`p`、`div`、`span`、`ul`、`ol`、`li`、`blockquote`、`code`、`pre`。
2. 不解释 `style`、事件属性（如 `onclick`）、`script`、`iframe`、`object`、`embed`、`form`、`video`、`audio`、`svg`、`math` 等标签或属性；其中可读文本按普通文本保留，执行/嵌入内容本身丢弃并记录为受控降级。
3. `a` 仅保留文字。普通 Markdown 链接由组件通过宿主回调交出 URL，组件不得直接导航；宿主负责 scheme/domain 校验、站内路由或用户确认。第三方 HTML 的 `a` 首发不交出 URL、更不打开 URL。
4. `img` 不直接请求 `src`；首发只保留安全的 `alt` 文本或空白占位。Markdown 图片必须经宿主 `ImageLoader`，首发默认仅 `https`，并由宿主执行 scheme/domain 白名单、重定向、大小、MIME 和超时校验。
5. 所有代码块只展示、语法高亮和复制，不执行代码；标记为 `html` 的代码块也不出现 WebView 预览/播放入口。
6. HTML 清理必须在任何富文本、图片加载、链接交互或 WebView 入口之前完成；不能仅依赖 UI 层隐藏按钮。

## 库与宿主的责任边界

| 领域 | GMarkdown 必须负责 | 宿主项目必须负责 |
| --- | --- | --- |
| 正确性 | 不跨块吞内容，提供确定的降级结果和可识别错误 | 决定书籍/章节/块的业务切分，并按约定调用组件 |
| 数据加载与刷新 | 不请求业务数据；对显式内容替换不残留旧 cell、不串内容、不自行插入或重排可见内容 | 网络请求、JSON/schema、缓存、分页、流式追加、章节切换、阅读锚点与业务刷新节奏 |
| 异步与生命周期 | 组件内部渲染任务可取消或失效，复用时不回填旧内容 | 在页面销毁或内容替换时调用约定的更新/释放接口 |
| 图片 | 提供 loader 注入、尺寸约束、失败状态和任务身份校验 | 提供鉴权、允许域名、缓存和业务占位策略 |
| 安全 | 危险能力默认关闭或最小授权，限制导航与资源访问 | 决定内容信任模型、域名白名单及是否启用 HTML/Mermaid |
| 性能 | 对给定 Markdown/chunks 避免无界缓存、巨大位图和不必要的主线程工作 | 决定请求、解析调度、章节大小、预加载与业务体验预算 |
| 诊断 | 提供不含正文的错误分类、耗时和降级信号 | 接入日志/埋点、告警和线上问题关联信息 |
| 发布回滚 | 提供版本、能力开关和已知降级说明 | 提供业务功能开关、灰度、监控和回滚执行人 |

责任边界没有确认时，对应门槛不得标记通过。

## 缺陷等级与准入规则

| 等级 | 例子 | 接入规则 |
| --- | --- | --- |
| P0 阻断 | 崩溃、死锁、内容跨块吞连、错误内容串到其他章节、任意代码/URL 越权执行、无法回滚 | 必须为 0 |
| P1 高风险 | 正常输入源码泄漏、正文或表格不可达裁切、明显卡死、内存持续增长、两条承诺路径结果实质不一致 | 必须为 0；若缩减功能范围，需在接入契约中明确关闭 |
| P2 可接受缺陷 | 局部基线偏移、非关键样式差异、受控降级、罕见且不丢内容的排版问题 | 必须有复现、影响范围、降级结果和后续负责人 |
| P3 优化项 | 视觉微调、非必要动画、诊断体验 | 可排入接入后，但不能伪装成已验证能力 |

“源数据本身错误”不自动等于可忽略：仍需证明渲染器不会扩大损坏范围，不会吞掉后续单元格、段落或章节。

每个风险与门槛都必须记录：适用性、负责人、目标阈值、验证环境、输入/操作次数、证据位置、提交号、当前状态。状态只允许“未开始 / 进行中 / 阻断 / 通过 / 不适用（附原因）”。P2 还可标记“接受”，但必须记录接受人和降级影响。

候选提交冻结后，任何影响解析、布局、异步任务、资源或公开 API 的代码改动，都会使相关门槛失效并需要重验；不能沿用旧截图或旧测试结果。

## 八道接入门槛

### G1：内容正确性与降级边界

目标是建立小而完整的固定回归集，不用全量人工翻书代替可重复验证。

- 公式：行内 `$...$`、独立 `$$...$$`、混合段落中的 `$$...$$`、标题/粗体/链接、列表/引用、表格、中文 `\text{}`、编号、化学扩展、多行 `aligned/cases/matrix`、超宽行内与块级公式、损坏定界符；失败时原文/占位降级。
- Markdown：标题、强调、删除线、链接、软换行、列表、引用、代码块、行内代码、表格、Markdown/HTML 图片、HTML、Mermaid。
- 保护边界：代码块、行内代码、URL、普通货币符号和转义美元中的公式样式文本不得被预处理器改写。
- 降级原则：只修复可由结构和边界共同确认的错误；不为任意孤立 `$`、任意 `\begin` 或未知宏自动补定界符；失败时保留可读文本或明确占位，不能显示半截源码后继续误解析。
- 主路径：固定样本以分块路径验证内容完整性、顺序、可达性和交互语义。TextView 仅保留已有探索证据；未来重新纳入时，必须独立补齐同一回归集，不从分块结果推断通过。

现有 B-001–B-010、T-001–T-003、I-001–I-002、F-007–F-008 中的分块结果可作为首发回归资产，不重复逐项探索。TextView 行内公式垂直对齐、超宽行内公式缩放/可读性属于延期项；分块路径仍需按首发能力补齐链接内公式、代码保护及其它契约内未覆盖样本。

通过证据：固定样本清单、原始内容、承诺路径结果、对应自动化用例和已知降级说明齐全；P0/P1 为 0。若只承诺一条路径，另一条必须明确标为诊断用途，而不是默认推断通过。

### G2：尺寸、主题与可访问性

- 宽度至少覆盖最窄支持 iPhone 竖屏、主力 iPhone 竖屏、iPad 竖屏、iPad 横屏和约定的一种窄分屏宽度；iPhone 横屏不在首发范围。
- 旋转、分屏、父视图改宽后，正文、图片、表格和公式必须按当前容器重新布局，不能继续使用启动时的 `UIScreen.main.bounds`。
- 覆盖浅色/深色、高对比度，以及宿主需要的 Dynamic Type 档位；表格、代码、公式图片和失败占位需保持可读。
- VoiceOver 至少能按合理顺序读到正文、链接、图片替代文字和交互控件；纯图片公式若无法提供语义，应明确记录首发限制。
- 文本选择、链接点击、代码复制、页面纵向滚动与表格/公式横向手势不得互相锁死。
- 正文选择以单个 `.Text` chunk 为边界：长按进入原生选择、双击选词，选择手柄/菜单只作用于当前 cell；不跨 cell 延展、不触发布局重算。手势仲裁需保证普通竖向 pan 优先保持页面滚动，cell 复用、内容替换和页面退出时必须取消选择状态与菜单，不能把旧文本或回调带入新 cell。
- 主题架构以语义 token（例如正文、标题、引用、代码、表格、链接、公式、边框、背景和失败态）承载颜色、字体和间距；系统 trait 只选择默认 token 集，宿主自定义主题使用同一入口。主题、字号与容器宽度应成为渲染/公式缓存键的一部分，主题切换只更新必要的可视结果，不重新解析 Markdown，也不在滚动期间重建可见块高度。

当前代码多处直接读取 `UIScreen.main`，因此“容器尺寸适配”是接入前审计项，不以单一 iPhone 17 竖屏截图判定通过。

### G3：生命周期、并发与故障恢复

- 调用方快速连续替换内容、反复调用更新或触发单元格复用时，旧图片/公式/高亮任务不得回填到新内容。
- 页面退出后异步任务能取消或安全失效；网络失败、超时、无效图片、MathJax 失败、内存警告均不崩溃。
- 分块路径的重复更新、cell 复用和退出必须验证。组件不承诺章节切换、分页或流式追加的业务策略；TextView 的设置、追加、清空和附件子视图回收延期至其重新进入正式范围。
- 全局插件管理器和共享缓存要明确线程模型、隔离规则与清理时机，避免测试或不同业务页面互相污染。
- 表格面对缺列、空行、异常 colspan/rowspan 等不可控输入时应返回可诊断降级，不能触发 `fatalError`。

通过证据：压力操作脚本或明确步骤可重复，连续多轮后内容不串、无崩溃、无持续增长，失败路径有日志或状态可定位。

### G4：性能与资源预算

阶段 A 先记录暂定预算和测量条件；第一次目标设备 Release 基线允许发起一次有记录的调整，但必须在性能修复和候选版本验证前冻结。不得测试结束后再按结果修改门槛，也不使用开发机上的单次体感代替预算。

目标设备口径仍为 iPhone 14 Pro Max / iOS 26.5.2（性能）与 iPad Air（M2）/ iOS 26.5（布局、分屏）；但当前项目只运行模拟器，不进行真机验证。模拟器结果可作为布局、方向、分屏和功能回归证据，不得作为真实设备的性能、滚动帧率或内存结论；阶段 E 的性能/内存项在无真机条件下必须标记为未测量或待补测。

首发性能预算（iPhone 14 Pro Max / iOS 26.5.2 / Release / 固定公式密集长章节）如下。计时从组件收到 Markdown 开始，到首屏内容稳定且可交互结束；网络请求不计入，屏外内容允许延后准备，但不得在滚动中造成高度跳变：

| 指标 | 阈值 |
| --- | --- |
| 首屏稳定可交互 | p95 ≤ 800 ms；p99 ≤ 1.2 s |
| 120Hz 正常连续滚动（60 秒）单帧主线程工作 | p95 ≤ 8.3 ms；p99 ≤ 16.7 ms |
| 滚动卡顿 | ≥ 50 ms 为 0；≥ 100 ms 为 0 |
| 滚动期布局 | 不因公式、图片、表格异步完成改变已显示块高度；不连续 `reload` 或 `invalidateLayout` |
| 可见区工作 | 不同步解析整章、生成公式位图、发起网络请求或进行无界缓存清理 |

内存预算（同一设备、Release、固定公式密集长章节）如下；退出页面后指组件已显式清空内容、页面释放，并经历一次系统内存警告。峰值不等于泄漏结论：重复操作后能回落并形成稳定平台才是主判据。

| 指标 | 阈值 |
| --- | --- |
| 单章渲染期间组件增量峰值内存 | ≤ 80 MB |
| 退出、清空并收到内存警告后稳定内存相对打开前的增量 | ≤ 20 MB |
| 公式/图片等组件缓存 | 必须按真实字节 cost 计量并有硬上限；合计 ≤ 32 MB |
| 同一章节连续打开/关闭 10 次 | 内存回落到稳定平台，不允许持续阶梯式增长；超过上述稳定增量即失败 |

若第一次 Release 基线无法达标，只能通过明确记录的架构调整、内容规模边界或受控降级修正；不得用隐藏加载或降低测量口径掩盖卡顿。

- 记录给定 Markdown/chunks 的首次渲染、缓存命中渲染、长内容滚动与连续替换内容的耗时分位数和主线程最长阻塞。
- 主线程只允许执行 UI 创建、一次快照提交和必要的可见布局；预处理、解析、分块、公式/代码的准备工作必须有可审计的线程归属。任何 UIKit、TextKit 或第三方对象若未证明可后台使用，必须留在主线程并拆分/限时，不能以“放到后台”掩盖线程安全问题。
- 首屏采用“准备完成后一次提交”的组件事务：内容身份、chunk 顺序和预估/最终尺寸在提交前固定。组件不得在用户滚动期间因为内部异步结果连续 `reload`、反复 `invalidateLayout` 或把已可见块撑高；图片、公式等延迟资源应预留稳定尺寸，无法安全预留时应在首次提交前完成或以明确降级显示。
- 内容替换以 generation/token 隔离：旧 generation 的后台结果一律丢弃；提交只作用于当前 generation。Diffable snapshot 的构造与 `apply` 都须在真实长章节测量主线程耗时，不能假定“无动画”就没有卡顿。
- 记录普通内容、公式密集内容、复杂表格内容的峰值内存，以及反复创建/销毁渲染视图后的稳定内存。
- 检查公式图片、富文本、WKWebView、表格附件和图片缓存的数量/成本上限；内存警告后可回收并恢复。
- 验证超长 Markdown、超长单元格、超宽公式和大量附件不会造成不可接受的同步工作或巨大位图。

- 性能预算需由宿主场景确认，例如首屏时间、主线程最长阻塞、允许峰值/回落内存和最低滚动帧率；计划中记录具体数值、设备、系统、Release/Debug 配置、章节规模、重复次数和测量工具。“明显”“持续”“不可接受”不能作为最终验收阈值。项目决定何时给组件内容；组件负责在拿到内容后不阻塞主线程、不制造滚动期布局抖动。

当前共享缓存设置了数量上限，但写入未提供实际 cost，不能据此宣称已有内存成本控制。

### G5：安全、隐私与外部资源

- 阶段 A 已确认服务端 Markdown、用户输入和第三方 HTML 都按不可信输入处理；这是架构输入，不得在功能完成后再改写。HTML、Mermaid、图片、链接和 HTML 代码预览必须分别做输入与导航策略审计。
- Mermaid 首发关闭；在代码入口实际关闭并验证前，仍视为 P0 未处置。第三方 HTML 已冻结为受限、非执行式展示，不能默认使用 `WKWebView` 执行。
- 第三方 HTML 按“第三方 HTML 首发安全规则”清理；HTML 预览不得默认赋予任意脚本/导航能力。Mermaid 首发关闭，未来启用时其源码注入、JS message handler、file URL 访问和 universal file access 必须收紧到实际需求。
- 图片加载限制 scheme、重定向、响应类型和体积，避免本地文件、内网地址或超大响应被任意读取；第三方 HTML 的 `img` 首发不直接请求资源。
- 相册、网络等权限只在用户触发相应功能时申请；不用的 Mermaid 图片保存能力应关闭或从接入范围移除。
- 记录第三方依赖许可证、资源来源和隐私清单需求；确认宿主的 ATS、CSP/导航策略及日志中不泄漏正文。

当前内容已按不可信输入冻结；不能把现有 WebView 配置泛化为可安全处理用户输入。

### G6：API、依赖与分发一致性

- 用一个最小宿主页面从零接入，验证初始化、样式、图片加载、链接/复制处理、更新和释放，README 示例必须能直接编译。
- 冻结首发公开 API，区分稳定 API、诊断 API 和内部实现；补充主线程要求、对象生命周期、错误/降级回调及线程安全说明。诊断事件至少覆盖解析/受控降级、公式失败、图片失败、渲染耗时和缓存命中，且默认不带 Markdown、公式原文或用户 URL。
- 只保留一条推荐用法，避免分块/TextView 的构建步骤、默认样式和插件注册各自隐含不同配置。
- 首发不承诺 SPM/CocoaPods；源码文件夹交付必须在全新 Xcode 工程中按清单直接加入 target 并构建。交付目录固定为不可修改的 `GMarkdown-<semver>/`；含组件、依赖、资源、`Integration.md`、许可证、变更说明和文件哈希清单，项目只能整体替换目录升级/回退。`Markdown`、`MPITextKit`、`SwiftMath`、`MathJaxSwift` 等传递依赖不能只写在说明中，必须随交付提供已核验的源码/二进制、版本、许可证和导入步骤。
- 校验资源在 Release 包中齐全且只包含首发需要的资源：代码高亮脚本与默认浅/深两套主题必须有 target membership 与 bundle 查找验证；Mermaid 已关闭，不应以首发功能名义携带或加载其执行资源；组件自有资源包 ≤ 1.2 MB。检查包体积和重复资源。
- 记录依赖锁定与升级策略，执行许可证和已知风险清单；发布使用语义化版本和变更记录。

通过证据：干净环境可按文档接入并构建，实际宿主也能构建运行，公开示例与当前 API 一致，无依赖解析漂移。

### G7：自动化、构建与发布回归

- 固定 fixture：从真实 JSONL 提取最小原文，记录书名、章节、块号、问题 ID 和原文哈希；fixture 不随排版修复被悄悄改写。

- 全量语料扫描：所有导入书籍逐块解析，记录崩溃、错误、公式/表格计数和耗时异常；它只证明结构安全，不代替视觉回归。

通过证据：命令、环境、提交号、成功结果和产物均写入最终验收记录；不能只写“用户之前编译正常”。

### G8：灰度、观测与回滚（宿主项目验收）

本门槛属于宿主项目验收，不是 GMarkdown 组件库的发布前置条件。组件库只需提供版本、能力开关、错误分类与不含正文的性能信号；项目自行完成：

- 业务功能开关、纯文本或旧渲染兜底，以及不发版关闭能力的路径。

- 灰度问题的业务版本、输入类别、渲染路径、系统/设备和回退状态关联。
