## 已确认的输入与边界

- `richTxt` 有内容时展示编辑器生成的 HTML 富文本；为空时展示 `txt` 的常见 Markdown。渲染失败不自动触发两者切换，后续动作交给项目决定。
- `richTxt` 样本使用标准 HTML 标签、数字字符实体，以及字号、颜色、段落和换行等阅读样式；现有样本还包含自定义标签 `<CustomClickableSpan>`。富文本支持以实际编辑器输出为范围，不承诺浏览器级 HTML/CSS 或脚本能力。
- `<CustomClickableSpan>` 标记可挖空文字，当前视觉要求是底部虚线。点击、挖空/恢复和业务状态规则仍由项目确定。
- 单独图片显示失败时，项目使用自己的自定义 Cell。组件需要提供可判断的失败或降级信息；能否替换嵌入 Markdown/表格中的图片，取决于目标页面如何组织内容块。
- `wordIndexBeans` 暂不接入，待产品确认具体业务语义后再讨论。

## 执行步骤

| 顺序 | 工作 | 交付与完成标准 |
| --- | --- | --- |
| 1 | **失败与降级通知**：梳理解析、富文本、公式和异步图片的失败位置；设计公开的结构化事件，包含可定位的内容块标识、原因、实际降级结果。明确图片加载器与组件各自负责发出什么事件。 | 宿主可以识别发生了什么、对应哪个块、屏幕上最终显示了什么，并决定是否改用业务兜底；可识别的失败不再只依赖日志。 |
| 2 | **输入选择与富文本展示**：落实 `richTxt` 优先、空值使用 `txt` 的输入契约；为编辑器 HTML 建立受控富文本处理路径，保留文本、段落/换行、数字字符实体及样本使用的字号、颜色等样式。 | 两类已提供的 `richTxt` 样本可阅读，文字不因数字实体或未知标签丢失；`txt` 的现有 Markdown 路径保持可用。 |
| 3 | **自定义标签**：识别 `<CustomClickableSpan>`，保留对应的文本范围，绘制底部虚线，并提供项目承接该范围的接口。 | 标签内文字和周围样式正常显示，项目能定位标记范围；不预设挖空/恢复的业务状态机。 |
| 4 | **定向确认**：用已提供的 Markdown、两类 `richTxt`、自定义标签和独立图片失败样本核对新增能力；检查回调信息是否足以触发项目自定义 Cell。 | 每项已确认要求都有明确结果；只补与改动相关的回归，不重新进行全量 Demo 测试。 |
| 5 | **目标工程接入**：取得业务工程源码或可操作的接入环境后，对接数据字段、页面列表、图片加载、链接处理和自定义 Cell；依据实际页面结构决定是否需要宿主列表使用的单块渲染接口。 | 真实页面能按 `richTxt`/`txt` 规则展示，失败能交由项目处理；完成业务工程编译与实际页面核对。 |

步骤 1～3 是当前明确的组件缺口。步骤 4 用真实样本核对这些改动；步骤 5 需要目标工程的实际页面和接口，不能仅凭 Demo 宣称已经接入。

### 步骤 1 当前进度

仓库 `Sources/` 已加入 `GMarkChunkGenerator.onRenderIssue` 和结构化 `GMarkRenderIssue`；它以每次渲染的 `generator.identifier` 加顶层 Markdown 块序号定位问题，区分公式退回原文、图片源或加载器缺失、图片加载失败、HTML 图片退回替代文字，以及独立图片处理器的空白显示。图片异步结果由新增的 `GMarkReportingImageLoader` 报告；原有 `ImageLoader` 仍可使用，但其内部失败不可观察。Demo 的 `NukeImageLoader` 已实现报告接口。

回调可能同步或异步发生，宿主更新 UI 前须切到主线程；每次内容版本使用唯一标识并忽略过期回调。该接口后来已同步到交付目录的 `Sources/`；候选尚未冻结。

## 实施时的判定原则

1. 失败通知只报告组件能够客观识别的失败和受控降级；“样式是否符合业务预期”仍须用页面和样本确认。
2. 单独图片的自定义 Cell 由业务列表选择。若图片位于 Markdown 或表格块内部，先确认宿主是否有可替换的块边界，再决定是否增加组件接口。
3. 发现实际编辑器 HTML 超出已给样本时，记录具体标签/样式及期望效果，按实际用途扩展支持范围。
4. 每次实现后检查完整改动和相关调用路径，再按当时可用的环境进行相应验证；未执行的构建或设备验证要明确记录。
